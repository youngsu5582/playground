# 학습 루프 — 레슨 하나 = 한 바퀴 (약 2시간 반)

시간은 기준이다. ① 20분 + ② 필수 글 분량(레슨마다 70~85분) + ③ 30분 + ④ 20분이라 한 바퀴가 2시간 반쯤이다 (01.04 는 ③ 이 40분). 한 번에 못 끝내면 단계 끝에서 멈추고 다음 날 이어서 한다.

"알고 있다" 의 기준은 하나다: **꼬리질문 5단을 버틴다** — 정의 → 동작 원리 → 왜 이렇게 설계했나(트레이드오프) → 언제 깨지나(장애 모드) → 내 경험 어디서 만났나.

| 단계 | 시간 | 하는 일 | 끝났다는 신호 |
|---|---:|---|---|
| ① 질문 · 첫 예측 | 20분 | README ① 의 질문에 **먼저** 종이로 답한다 (NOTES §0). 이어서 예측 칸 `"?"` 를 **감으로** 채워 `NN.NN-predict` 를 돌린다 — 읽기 전이라 틀려도 된다 | NOTES §0 이 채워졌다 · `"?"` 가 0곳이다 |
| ② 원리 | 필수 글 분량대로 (레슨 README ② 제목의 N분 — 필수 글자 수 ÷ 400자/분, 5분 단위) | 레슨 `docs/` 의 **필수** 글(README ② 표 첫 행 · docs/README 의 "구분" 열)을 읽으며, ① 에서 틀린 문항이 **왜** 틀렸는지 찾는다. 1차 자료(공식 문서 · 소스 · 책)는 "찾을 것" 목록을 들고 연다. 그림을 **직접** 그려 본다 | 틀린 문항마다 이유 한 줄 |
| ③ 재현 | 30분 | **틀린 예측 되짚기**(NOTES §1 → 실제 값으로 고쳐 `NN.NN-predict` 초록) → **구현**(`NN.NN-implement`) → **관찰**(`observe/`) | 테스트 초록 · 관찰한 것을 한 줄씩 적었다 |
| ④ 내 말로 | 20분 | NOTES §2~5 를 채움 · §6 내 실무와 연결(권장) → 레슨 docs 의 면접 사다리(30초 답 → 2분 답 → 사다리)를 소리 내어 → `/kata:discuss <주제>` | 해설을 펼치기 전에 5개 다 답했다 |
| (루프 밖) 심화 | — | 레슨 docs 의 **심화** 글 — 꼬리질문 · 깊은 지식 대비. 레슨을 마친 뒤 · 면접 전 복습 | — |

순서의 이유: 읽고 나서 예측하면 글에서 답을 찾아 적게 된다. **먼저 감으로 틀려 보고** 읽어야 글의 어느 문장이 내 오해를 고치는지 보인다. 필수 글은 ① 의 예측 문항과 구현 빈칸을 되짚는 데 필요한 최소 묶음이다 (필수 글에 든 MySQL 절은 "(심화)" — 회사 서비스가 PostgreSQL 이라 비교 참고다).

## NOTES 칸은 언제 채우나

| 칸 | 시점 |
|---|---|
| §0 돌리기 전에 적은 답 | ① 에서 (README ① 질문에 답한 직후, 첫 예측을 돌리기 전) |
| §1 틀린 예측 | 첫 예측을 돌려 빗나간 문항이 나오는 **즉시** (①) — 이유 칸(왜)은 ② 를 읽으며 · ③ 되짚기에서 채운다. 나중에 몰아 쓰지 않는다 |
| 관찰 메모 | ③ 의 관찰 중 (메시지 원문 · 본 것 · 예측과 다른 것) |
| §2 그림 · §3 3분 설명 · §4 꼬리질문 · §5 회차 기록 | ④ 에서 |
| §6 내 실무와 연결 (권장) | ④ 에서 — 비워도 끝낼 수 있다 |

## 규칙

- **예측은 돌리기 전에 — 감으로, ① 에서.** `String 예측 = "?";` 그대로 돌리면 실제 값을 보여 주지 않는다. 읽기 전이라 틀려도 된다. 틀린 예측은 돌릴 때마다 바로 NOTES §1 에 — 제일 남는 칸이다.
- **예측이 틀리면.** ① 내 예측 · 실제를 NOTES §1 에 적는다 → ② 필수 글을 읽고 왜 다른가를 한 줄로 채운다 → ③ 예측을 실제 값으로 고쳐 그 문항을 초록으로 만든다 (고친 값은 적중으로 세지 않는다).
- **구현은 TODO(구현) 하나씩.** 고치고 → 돌리고 → 다음. 실패 메시지가 "무엇이 깨졌고 어디를 고치나" 를 말해 준다.
- **정답 patch 는 초록 다음에.** `solutions/NN.NN.patch` 와 내 코드를 비교한다 — 경계값 · 동시성 · 예외 처리에서 무엇이 다른가.
- **AI 는 ④ 에서.** 구현을 시키지 않는다. 막히면 "힌트만" 을 요청한다. 꼬리질문 면접관 역할은 적극 시킨다.
- **시간이 넘으면 멈춘다.** 단계 시간(레슨 README 제목의 N분)을 크게 넘기면 한 단계가 끝난 자리에서 멈춘다. NOTES §5 회차 기록에 "막힌 곳 · 다음 한 걸음" 을 적고 다음 날 이어서 (강박 내려놓기).

## 완료의 두 칸 — 완료 기준은 여기서만 정의한다

[PROGRESS.md](PROGRESS.md) 에서 두 칸을 **따로** 체크한다. 둘 다 ✅ 여야 레슨이 끝난 것이다.

- 테스트 ✅ — `./gradlew NN.NN` 전부 초록 (예측 + 구현)
- 내 말로 ✅ — NOTES 를 채웠고(§6 은 권장이라 비워도 된다), 레슨 README 의 3분 설명을 그림 없이 해 봤고, 꼬리질문 5개를 **해설을 보기 전에** 답했다

예측 적중 = 예측 테스트의 **문항(테스트 메서드) 수** 중 **① 에서 감으로 처음 적은 예측**이 맞은 수다. 글을 읽고 다시 적어 고친 문항은 적중에 안 든다. `"?"` 그대로(예측을 적기 전에) 돌린 것은 시도로 세지 않는다.

기존 playground 들은 테스트만 초록이고 기록이 비는 일이 많았다. 내 말로 ✅ 가 없으면 그 레슨은 끝난 게 아니다.
