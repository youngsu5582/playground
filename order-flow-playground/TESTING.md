## 관찰 규율

### 1. 동시성 테스트는 1회 초록이 증명이 아니다

경쟁 상태는 확률적이다. 반드시 반복한다.

```java
ConcurrencyHarness.repeat(200, () -> { /* 시나리오 */ });
```

200회 중 1회만 실패해도 **버그가 있는 것**이다. "가끔 실패하니까 재실행" 은 금지 — 그 습관이 붙으면 진짜 버그를 놓친다.

### 2. 깨지는 걸 먼저 본다

stage3 은 **락 없는 구현으로 한 번 실패시키고 시작**한다. `successCount = 13` 을 눈으로 봐야 이 문제가 자기 것이 된다.
stage5 는 `new ArrayList<>(priorityQueue)` 로 일부러 틀리게 짜서 힙의 부분 순서를 확인한다.

관찰 없이 정답 코드를 쓰면, 나중에도 이론으로만 말하게 된다.

### 3. 불변식은 매 테스트 끝에

stage3 은 모든 테스트 마지막에 `onHand = available + reserved` 를 확인한다.
개별 연산이 맞는지보다, **어떤 조합을 거쳐도 총량이 유지되는지**가 재고 버그의 90%를 잡는다.

### 4. 결정론

같은 입력에 같은 출력이 안 나오면 테스트가 아니다.
- 정렬은 마지막 tie-breaker 까지
- 시간은 고정 `Instant` (`T0`) — `Instant.now()` 를 테스트에 쓰지 않는다
- 랜덤을 쓰면 seed 고정
